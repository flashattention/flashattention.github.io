AI 에이전트와 일하는 방식 구현은 에이전트가, 문제 정의와 통과 기준과 검수는 제가 맡습니다.

  1. 지시서로 쪼개고, 하나씩 검수합니다

    에이전트가 일부만 하고 끝났다고 보고하는 문제를 "지시 → 작업 지시서 → 하나씩 수행 → 스크린샷 검수 → 커밋" 규칙(CLAUDE.md)으로 해결했습니다.

  2. 통과 기준은 숫자로 정합니다

    봇 시뮬레이션으로 점령전 공격팀 승률을 76~84%에서 50~57%로 맞췄고, 신규 맵 30종은 자동 플레이 봇이 3개 난이도를 완주한 것만 내보냈습니다.

  3. 결정과 이유를 남기고, 틀리면 되돌립니다

    모바일 의견으로 바꾼 조작을, 기록 경쟁 게임은 기기마다 규칙이 달라선 안 된다는 원칙을 세워 되돌리고 의사결정 기록에 남겼습니다.

  4. 외부 데이터로 만든 결과는 화면으로 확인합니다

    북촌 한옥마을이 붉은 벽돌 동네로 그려진 것을 화면 검수에서 찾아, 건축물대장 구조 코드 범위 오류를 고쳤습니다.

에이전트 이전에는 직접 구현했습니다.논문 실험 코드(BERT 11종 파인튜닝과 앙상블), 캡스톤 SPEIS의 예측 모델·챗봇·React 화면, 해커톤의 React/Node.js 풀스택과 AWS EC2 배포·CI/CD. 그래서 에이전트가 쓴 코드의 구조를 읽고 판단할 수 있습니다.
