AI 에이전트와 일하는 방식

구현은 에이전트가, 문제 정의와 통과 기준과 검수는 제가 맡습니다. 이 분업이 실제로 돌아가게 만든 규칙 네 가지입니다.

  1. 지시서로 쪼개고, 하나씩 검수합니다

    지시가 쌓이면 에이전트가 일부만 하고 끝났다고 보고하는 문제가 있었습니다. "지시 → 작업 지시서에 구체화 → 하나씩 수행 → 스크린샷 검수 → 커밋" 규칙을 저장소의 작업 규칙 파일에 넣어 해결했습니다.

    작업 규칙 (CLAUDE.md)

  2. 통과 기준은 숫자로 정합니다

    서버 코드를 빠른 가짜 시계로 수천 판 돌리는 봇 시뮬레이션으로 점령전 공격팀 승률을 76~84%에서 50~57%로 맞췄습니다. 신규 맵 30종은 자동 플레이 봇(빔 탐색)이 3개 난이도를 모두 완주한 것만 내보냈습니다.

  3. 결정과 이유를 남기고, 틀리면 되돌립니다

    모바일 의견을 듣고 숙이기 조작을 바꿨다가, 기록 경쟁 게임은 기기마다 규칙이 달라서는 안 된다는 원칙을 세우고 되돌렸습니다. 이런 판단과 근거를 의사결정 기록으로 남깁니다.

    의사결정 기록

  4. 외부 데이터로 만든 결과는 화면으로 확인합니다

    북촌 한옥마을이 붉은 벽돌 동네로 그려진 것을 화면 검수에서 발견했습니다. 원인은 건축물대장 구조 코드 범위 오류였고, 실제 코드 분포를 뽑아 고쳤습니다.

에이전트 이전에는 직접 구현했습니다. 논문 실험 코드(BERT 11종 파인튜닝과 앙상블), 캡스톤 SPEIS의 예측 모델·챗봇·React 화면, 해커톤의 React/Node.js 풀스택과 AWS EC2 배포·CI/CD. 전공에서는 자료구조, 운영체제, 데이터사이언스, 선형대수학 등 7과목에서 A+를 받았습니다. 그래서 에이전트가 쓴 코드의 구조를 읽고 판단할 수 있습니다.
